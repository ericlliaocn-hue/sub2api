ANYTOKEN / API DOCS

AnyToken API 文档

AnyToken 提供 OpenAI、Anthropic 和 Grok 兼容接口。你可以继续使用熟悉的 SDK 与开发工具，只需替换 API 地址和密钥。

开始接入 → 查看可用模型 ↗
推荐 OpenAI 兼容 Base URL https://api.anytoken.work/v1
01统一入口

一个 API Key 调用多个模型与渠道。

02兼容现有工具

支持常用 SDK、Codex CLI 与 Claude Code。

03用量透明

请求、Token、费用与状态均可追踪。

01 / QUICKSTART

快速开始

完成一次 API 请求只需要三步。

  1. 1
    登录控制台

    前往 anytoken.work 注册或登录。

  2. 2
    创建 API Key

    在「API 密钥」页面创建密钥，并立即保存。密钥只应交给可信客户端。

  3. 3
    发送请求

    使用模型广场中可用的模型名，向 API 域名发送请求。

终端
curl https://api.anytoken.work/v1/responses \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-sol",
    "input": "用一句话介绍 AnyToken"
  }'
模型名称示例模型仅用于展示。实际调用前，请到模型广场确认当前可用模型及所属分组。
02 / ENDPOINTS

地址与路径

官网与模型 API 使用不同域名。开发工具中请填写 api.anytoken.work，不要填写官网域名。

用途推荐地址说明
官网 / 控制台https://anytoken.work登录、密钥、模型和用量管理
OpenAI 兼容 Base URLhttps://api.anytoken.work/v1多数 OpenAI SDK 与客户端填写此地址
Anthropic 兼容 Hosthttps://api.anytoken.workClaude Code 会自行追加 /v1/messages
Gemini 原生 Hosthttps://api.anytoken.workGemini CLI 会使用 /v1beta 路径
文档https://doc.anytoken.work你当前正在阅读的站点
/v1 要不要填写？取决于配置项含义。名为 Base URL 的 OpenAI 兼容配置通常填写到 /v1；Claude Code 的 ANTHROPIC_BASE_URL 和 Gemini CLI 的 Host 填域名根地址。最终请求路径仍会包含对应版本前缀。
03 / AUTH

身份验证

所有模型请求都需要在 HTTP Header 中携带 API Key。

HTTP Header
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

部分 Anthropic 兼容客户端会使用 x-api-key，官方客户端配置方式见下方 Claude Code 章节。

04 / API

Responses API

新项目推荐使用 Responses API。它使用统一的 input 输入格式，并支持文本、工具调用等能力。

POST/v1/responses
请求体
{
  "model": "gpt-5.6-sol",
  "input": [
    {
      "role": "user",
      "content": "写一个三行的产品介绍"
    }
  ]
}
05 / API

Chat Completions

兼容使用 messages 的既有 OpenAI 客户端。

POST/v1/chat/completions
cURL
curl https://api.anytoken.work/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.6-sol",
    "messages": [{"role": "user", "content": "你好"}]
  }'
06 / API

查询可用模型

使用当前密钥查询它所在分组可访问的模型。不同密钥看到的列表可能不同。

GET/v1/models
cURL
curl https://api.anytoken.work/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
07 / STREAMING

流式响应

在支持的接口中加入 "stream": true，服务会以 SSE 事件流持续返回结果。客户端应读取直到流正常结束。

请求片段
{
  "model": "gpt-5.6-sol",
  "input": "逐步解释快速排序",
  "stream": true
}
08 / SDK

OpenAI SDK

Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://api.anytoken.work/v1",
)

response = client.responses.create(
    model="gpt-5.6-sol",
    input="你好，请介绍一下你自己。",
)
print(response.output_text)
Node.js
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: "YOUR_API_KEY",
  baseURL: "https://api.anytoken.work/v1",
});

const response = await client.responses.create({
  model: "gpt-5.6-sol",
  input: "你好，请介绍一下你自己。",
});
console.log(response.output_text);
09 / TOOLS

Codex CLI

将密钥放入环境变量，再在用户配置中新增 AnyToken Provider。这样密钥不会写进配置文件。

1. 配置环境变量

终端
export ANYTOKEN_API_KEY="YOUR_API_KEY"
PowerShell
$env:ANYTOKEN_API_KEY="YOUR_API_KEY"

2. 编辑配置文件

macOS/Linux：~/.codex/config.toml；Windows：%USERPROFILE%\.codex\config.toml。

config.toml
model_provider = "anytoken"
model = "gpt-5.6-sol"

[model_providers.anytoken]
name = "AnyToken"
base_url = "https://api.anytoken.work/v1"
env_key = "ANYTOKEN_API_KEY"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
关于配置Codex 自定义 Provider 当前使用 Responses 协议。模型名请按模型广场实际可用项填写。

claude
PowerShell

$env:ANTHROPIC_AUTH_TOKEN="YOUR_API_KEY"
$env:CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC="1"

claude

13 / BILLING

用量与计费

每次成功调用后，可在控制台的「使用记录」中查看模型、Token、实际费用、请求状态和耗时。

实际费用

本次请求从账户余额扣除的金额。

Token

按输入、输出及缓存类型统计的模型用量。

分组

决定当前密钥可以使用的模型、渠道和计费倍率。

请求记录

用于核对调用时间、模型、端点、状态和费用。

价格以哪里为准？模型和渠道会动态调整。调用前请以模型广场展示的当前价格与分组倍率为准。
14 / TROUBLESHOOTING

错误排查

现象 / 状态码常见原因处理方式
400请求结构、参数或模型能力不匹配检查 JSON、接口协议和模型支持项
401API Key 缺失、无效或已撤销检查 Authorization Header 并重新复制密钥
403密钥、分组或客户端限制检查密钥绑定分组及访问规则
404域名或路径错误确认使用 api.anytoken.work 和正确版本路径
429余额、额度、并发或频率限制查看余额和限制，退避后重试
5xx服务或模型渠道暂时异常保留请求时间与错误内容，稍后重试或联系客服
no such hostDNS 无法解析 API 域名检查域名是否拼错、本地 DNS、代理和网络设置
15 / SECURITY

密钥安全

  • 只在服务端或可信本地工具中使用 API Key。
  • 不要把 Key 写入网页前端、公开仓库、截图或聊天记录。
  • 优先使用环境变量或系统密钥管理工具保存 Key。
  • 怀疑泄露时立即在控制台撤销旧 Key，并创建新 Key。
  • 为不同项目创建独立 Key，便于审计与单独撤销。
16 / FAQ

常见问题

为什么官网地址不能直接调用模型？

anytoken.work 只提供官网和控制台；模型请求统一发送到 api.anytoken.work，便于安全隔离和客户端配置。

为什么有时填域名，有时要加 /v1？

OpenAI 兼容 SDK 的 Base URL 通常包含 /v1。Claude Code、Gemini CLI 等工具会自行拼接协议路径，因此按本文对应章节填写。

模型名称从哪里获取？

前往模型广场查看，或使用当前 API Key 请求 GET /v1/models。密钥所属分组会影响可用模型。

请求成功但客户端没有显示完整内容？

先检查是否开启流式输出，以及客户端是否完整读取 SSE 数据；再到使用记录中确认请求状态和输出 Token。

如何获得帮助？

联系客服时请提供请求时间、接口路径、模型名和完整错误信息。不要发送真实 API Key。
